# From Manual Bottleneck to Repeatable AI Workflow
*Vehicle Data Maintenance at an Automotive OEM — Engineering Services (case anonymized)*

**TL;DR** — A manual data-maintenance task, executed under a 2-hour window and prone to errors that surfaced only at the next release, was turned into a repeatable Copilot-powered workflow: **zero manual errors across 9 consecutive deliveries, ~60% time reduction, documented and handed over to colleagues.** The key was not the AI — it was finding the right bottleneck, encoding domain rules into the prompt, and building a verification loop.

## 1. Context
Vehicle data for automotive OEM projects is maintained in a central data platform using data files. The maintenance cycle:
1. Receive a stakeholder file with new values
2. Download the required labels from the data platform (as a data file)
3. Update the label values in the data file
4. Upload the file back to the data platform

## 2. The problem — three failure vectors
- **Manual and error-prone**: file batches were generated by hand; mistakes were often invisible until the next release, when a data deviation finally surfaced.
- **Extreme time pressure**: the maintenance window was sometimes only 2 hours — preparing *and verifying* the whole file set within it was critical and stressful.
- **Hidden domain complexity**: multiple vehicle IDs per file, each with multiple labels; each label carries two values (primary value = authoritative, parallel value = to be ignored); decimal separator differs between stakeholder file (`.`) and the platform file (`,` — German convention); only labels present in the stakeholder file may change; labels missing from the data platform must be reported, never invented.

## 3. The approach — find the bottleneck, build around it
Instead of automating "the whole process", I analyzed where time and error risk actually concentrated, then built around that bottleneck:
- designed a data file template
- configured Copilot to generate the full file batch from the template
- tuned the prompts so each file is adjusted to its specific input data

## 4. Prompt iteration — three versions, three real failure modes fixed
- **v1** conversational instruction ("change vehicle 8 to vehicle x…") — worked, but output drifted and nothing was verified
- **v2** specification — role definition, task decomposition (filter → update → rename → verify), output contract (deviation-report table), decimal-separator rule, ambiguous-input guard
- **v3** governance logic — primary value as single source of truth (parallel value never written), missing-label reporting, one output file per ID for traceability

Each version was driven by a real failure or constraint found in use — **the prompt was treated as a product, iterated with feedback.**

## 5. Results
- Zero manual errors across 9 consecutive deliveries
- ~60% reduction in working time for this task
- The task stopped being a bottleneck in the tight maintenance window
- Process standardized in an SOP; 2 colleagues coached to run the workflow independently

## 6. Beyond the tool
The tool was the easy part. The durable value: an SOP, trained colleagues, a workflow that no longer depends on one person. **The capability outlives the builder.**

## 7. The transferable method (AI-enablement playbook)
1. **Find the repetitive bottleneck** — the step that repeats, consumes time, and carries the highest error cost
2. **Build the minimal solution around it** — template + AI tool + tuned prompts
3. **Encode domain rules into the prompt** — the model doesn't know your domain (decimal commas, authoritative data sources, missing-label policy); you encode them
4. **Build a verification loop** — the model checks its own output against the source of truth and reports deviations instead of silently "fixing" them
5. **Standardize and enable** — SOP + coaching, so the capability outlives the builder
